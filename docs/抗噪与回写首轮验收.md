## 已实现什么

### 语音起始确认

原程序在 VAD 判断正在说话后立即打断播报。现在额外要求默认持续 80 ms，并且去直流能量不低于 -50 dBFS，才取消旧输出、进入识别；原有 300 ms 前置音频仍保留。

这一步针对短促误触发和低能量噪声，不修改 PCM 波形，也不能分离持续背景人声。已验证数学合成 PCM 在短脉冲、低能量、直流偏置、较轻声、不同帧长和重新起始条件下的门控行为。测试中的 VAD 标记受控，不等于已运行真实声学模型。

可通过 `ZHIYU_SPEECH_CONFIRM_MS` 调整确认时长，通过 `ZHIYU_SPEECH_MIN_DBFS` 调整能量门槛，具体范围见 `.env.example`。实际麦克风上需要兼顾短回答和轻声，不能为了减少误打断而无限提高阈值。确认机制可能增加打断等待时间，需要实测。

### 按任务回查持久化结果

新增受现有访问认证保护的接口：

`GET /api/cases/{case_id}/result`

返回内容包括：

| 字段 | 含义 |
| --- | --- |
| case_id / case_version | 任务编号和当前申请单版本 |
| task_status | pending：没有已提交回执；processed：已有处理结果；needs_human：最新结果要求人工 |
| latest_outcome | 最新已提交回执，含会话、联系状态、商家意愿、推荐渠道、回执及后续事件编号 |

`processed` 表示任务已有处理记录，不代表商家已补交或资质审核通过。重新启动程序后可以按任务查询，无需记住原会话；查询不会再次执行写入或重新创建跟进事件。

接口复用原 operations 表，以同一读取快照取得任务版本和回执，不迁移或覆盖现有库。原有按会话和按回执编号的查询仍可使用，原业务确认及幂等事务条件不变。
