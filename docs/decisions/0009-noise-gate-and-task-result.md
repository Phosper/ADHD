# 0009 语音起始确认与按任务回查结果

日期：2026-11-14。状态：候选实现，待团队评审及真人噪声验收。

## 背景

原语音入口在 Silero 判定 SPEAKING 后立即取消播报，缺少额外的持续时间和低能量误触发保护。浏览器已请求回声消除和降噪，但请求参数不能证明麦克风在实际环境中的抗噪效果。

原回写使用 SQLite 事务持久化会话、业务回执及申请单版本，已提供按回执编号查询；缺少按任务查询最新结果的公共接口，调用方必须先拿到原会话或回执编号。

浏览器约束语义参考 [Media Capture and Streams 规范](https://w3c.github.io/mediacapture-main/#dom-mediatrackconstraintset-noisesuppression)及 [MDN noiseSuppression 说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/noiseSuppression)。

## 决定

1. 在 VAD 判为持续语音后，额外确认默认 80 ms 且去直流能量不低于 -50 dBFS，才取消旧播报并开始 ASR。保留既有 300 ms 前置音频，减少确认阶段裁掉词首的风险；不在语句中途对 PCM 做硬切静音。
2. 参数由 ZHIYU_SPEECH_CONFIRM_MS（20—150 ms）和 ZHIYU_SPEECH_MIN_DBFS（-96 至 -10 dBFS）配置，拒绝无效数值。每次有效语音起始记录 speech.confirmed 的实际阈值。
3. 新增 CaseResult 契约和受既有认证保护的 GET /api/cases/{case_id}/result，从同一 SQLite 读取快照返回当前申请版本及最新已提交回执。无需数据库迁移，也不改原事务写入权限与条件。
4. task_status 为 pending（尚无已提交回执）、processed（已有处理结果）、needs_human（最新回执要求人工）。processed 表示一次任务已有处理记录，不表示整改材料提交或资审通过。latest_outcome 保留具体业务结果、渠道与后续事件编号。

## 取舍和验收

该语音门控只抑制短促或低能量的误触发，不是波形降噪器，无法保证分离持续背景人声。新增确认会增加语音起始判定时间；仍需用实际麦克风测试轻声、短回答、打断与首字时延，不能据逻辑测试宣布比赛抗噪达标。

回写验证覆盖最终确认前不产生回执、最终提交持久化及重启回查、重复请求返回相同回执、同任务多次沟通查询最新结果、写入后审计失败时整笔回退，以及接口认证和不存在任务。使用独立合成库，不修改已有运行库，也未接京麦真实接口。

回退：恢复此前语音入口代码即可取消本次门控；新增结果查询为兼容性接口。数据库结构未变，回退代码无需恢复或覆盖业务数据。
