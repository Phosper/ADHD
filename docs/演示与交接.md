# 基线演示与交接

当前是可运行的工程候选版。展示时说明“合成任务、自建 Mock 回写”，不能展示成实际企业工单已关单。网络许可、官方接口与人工验收未完成，不能称比赛就绪。

## 本机使用

1. 按 deploy/README.md 保持校园 SSH 研发连接与三模型服务可用。
2. 根目录设置 ZHIYU_MODEL_MANIFEST 指向 runtime/model-manifest.json，使用 `.voice/Scripts/python.exe -m scripts.launch --real`。访问 http://127.0.0.1:18080 。没有模型时可用 `.venv/Scripts/python.exe -m scripts.launch` 体验文字 Mock。
3. 选择合成任务，开始新会话，然后点击“接入实时语音”。耳机测试能减少回声；接入前浏览器会请求麦克风权限。默认不归档原始录音，会保存会话转写、事件和业务结果。
4. 自然表达“我是负责人”“现在方便”“我会补齐盖章页重新提交”“确认”。每句话听完回复后再继续；四轮后应出现 will_resubmit 回执。不要把“知道了”当作整改承诺。
5. 另开一通，在开场中途讲话，检查停播。另测错人、拒绝、改口、要求人工和询问是否保证通过。使用“结束会话”收尾，保留失败会话，不删除或覆盖。
6. 在工作台查看和导出会话/事件/报告。以 session_id 和 trace_id 对照运行数据库；原始资料、会话导出和音频只留私有目录。

若团队需要录音验收，事先告知参与人员，设置 ZHIYU_RECORD_AUDIO=1 后重启本项目 API。生成音频 PCM、浏览器播放回执与人实际听到的声音是三类证据，不能互相替代。正式声学测量方法等待赛题组确认。

## 团队交接

- 开发者使用独立分支/工作目录，不共用可写目录。本次仅有本地提交，没有推送或合并；私有远程、分支保护与远程 CI 待团队配置。
- 业务复核人按来源逐条审查导入结果，用 scripts/review_knowledge.py 生成新审核快照；不能直接改旧资料或把隐藏表并入现行规则。
- 验收人员另拟独立用例并记录结论；本项目已有开发用例不能重新命名为独立 holdout。贡献说明由实际参与者填写，不能替他人编造贡献。
- 交付源码及哈希参见基线自测报告。恢复使用新目录；回退代码不回滚外部业务事实，日志保留，旧回执禁止重复执行。
