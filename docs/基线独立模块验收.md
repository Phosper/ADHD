## 不依赖网页或模型的运行方法

在项目根目录使用现有业务 Python 环境：

```text
python -m scripts.verify
python -m evals.run_writeback
```

回写工具默认读取 `evals/cases/writeback_component.json`，可以用 `--suite` 指定同格式合成案件，用 `--output-dir` 指定报告目录。每次使用独立临时数据库，最终 JSON 报告保留到 runtime/evals，失败时返回非零退出码。

报告包含每一轮的受控意图、前后阶段、确认标记和数据库结果，以及最终会话、回执和逐项判定。输入明确是“已经识别好的意图”；即使附有便于阅读的商家句子，也没有调用模型理解这些句子。因此 12/12 证明的是业务层和回写层，不能用作语言理解准确率。

12 个用例覆盖三种合成材料问题的完整流程、知悉但未承诺、改口撤回、改口后重新确认、接错人、拒绝、忙需跟进、要求人工、低置信度确认和最终确认前断开。另检查逐轮无提前提交、重复最终请求、重启回查、跟进回执、正确案件动作及连续事件序号。

当前有效报告：

- `runtime/evals/writeback-7a98297b30d34d6a89c123cf4e38a92e.json`：本轮 12 个受控意图用例。
- `runtime/evals/text-3a70323eb354436787486bf6488ad6c3.json`：既有 8 个文本开发用例。

这些均是开发与模块验收资料，不是封存独立测试集或官方成绩。

## 对队友的接口约定

语音模块继续接收 16 kHz、单声道、int16 PCM，以及真实 VAD 状态；分段器输出开始／结束标记、600 ms 非最终块和最后一个结束块。门控未确认前不会产生识别块，下一句话不继承前一条已结束语音。只有真正送入完整链路，才能检查模型识别和实际播放。

业务模块继续使用已有意图种类、会话版本、案件来源和渠道字段。回写结果通过既有会话／回执接口及新增的 `/api/cases/{case_id}/result` 查询，本轮不改变这些接口。

待前端和模型准备好后，沿用同一批案件与预期结果，改用真实声音和模型输出联调；同时补实际问答、渠道选择、播放取消、误打断、短回答漏检和端到端时延。没有这一步，不能标记基线整体验收完成。
