# 副线 让有用的经验帮助下一次任务

**研究目标：判断哪些处理经验适合当前任务，并验证它们是否带来了额外收益。** 这是智语外呼 RSI 主线的支持方向，建议在评测方法稳定、有人手独立负责时开展。

## 1 经验记忆与业务知识有什么区别

业务知识回答“材料要满足什么要求”；经验记忆回答“遇到某类表达或困难时，怎样处理更合适”。例如，“需要补齐某项材料”是业务知识，“用户只说知道了时，还要确认实际意愿”是处理经验。

本方向保存可复用的工作方法，不以长期收集商家个人信息为目标。经验也不能修改业务规则：一次通话成功，不代表其中的材料要求、身份判断或渠道选择都可以变成新规定。

## 2 已有研究与参考来源

| 工作与来源 | 已有方法 | 在本项目中的用途 |
| --- | --- | --- |
| **ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory**：[论文](https://arxiv.org/abs/2509.25140) · [代码](https://github.com/google-research/reasoning-bank) | 从成功和失败轨迹提炼可复用经验 | 参考“存什么、如何表达经验” |
| **MemRL: Self-Evolving Agents via Runtime Reinforcement Learning on Episodic Memory**：[论文](https://arxiv.org/abs/2601.03192v2) · [代码](https://github.com/MemTensor/MemRL) | 根据环境反馈更新经验效用，检索时结合相关性与效用 | 参考“先选哪些相关经验，再优先使用哪些” |

提炼经验、按相似度检索、给成功经验加分都已有研究。值得进一步检验的是：**用了某条经验以后成功，是否说明成功是这条经验带来的？这种收益在什么条件下会消失？**

## 3 用一个例子说明研究空间

假设经验是“遇到疑问就完整重复材料要求”。它在简单任务中可能经常伴随成功，但用户本来就愿意配合，重复规则未必有帮助。在复杂通话中，长篇重复还可能增加时延和无效轮次。

因此，经验的价值不能只按“使用后成功次数”累计。可以在相同初始案件和用户条件下，比较使用与不使用某条经验的结果，并区分业务场景、阶段和规则版本。模拟用户会随系统回复改变行为，这种比较需要重复运行；一次差值不能当作真实人群的因果结论。

## 4 怎样接入当前基线

ADHD 当前检索器只检索已审核的业务知识，模型主要做意图分类，没有经验库和效用更新。最小接法是将少量相关经验作为分类请求的补充：输入当前阶段、上一句问题、商家表达，检索有用的分类经验，然后仍输出原有意图格式。

当前模型服务输入长度有限，经验必须有数量和长度预算。初期无需为了少量经验引入复杂数据库。建议保存以下内容：

| 内容 | 用途 |
| --- | --- |
| 适用场景、阶段与规则版本 | 防止经验用错地方或沿用过期规则 |
| 具体处理方法 | 明确如何帮助分类或沟通，避免只存空泛总结 |
| 支持案例与反例 | 保留经验有效和失效的证据 |
| 效用、样本量与不确定性 | 区分偶然成功与较稳定收益 |
| 停用条件 | 规则改变或反例增多时退出检索 |

先按适用条件筛选，再按相关性和效用选择；业务知识与处理经验分别管理。会话要记录实际使用的经验及版本，便于复查。

如果后续研究“先问什么、怎样解释”，则必须先补受控策略接口。当前状态机固定生成回复，检索到一条沟通建议并不意味着系统有能力执行它。代码参考：[当前知识检索器](https://github.com/Phosper/ADHD/blob/41afa0c67904de9ef07a5d1445dbcfb86e1e7565/packages/knowledge/retrieve.py)、[模型调用入口](https://github.com/Phosper/ADHD/blob/41afa0c67904de9ef07a5d1445dbcfb86e1e7565/services/api/model_client.py)。

## 5 怎样比较

固定模型、Skill、数据划分和输入长度预算，至少比较：不使用记忆、固定少样例提示、只按相关性检索、普通效用检索、按条件估计额外收益的方法。增加随机经验或打乱效用值的对照，检查收益是否只是“多给了几个例子”。

评价业务错误、分类准确率、正确澄清/转人工、输入长度和响应时延；如果业务规则版本改变，还要检查是否错误沿用旧经验。多个经验共同使用可能互相影响，应保留单条与组合的对照。

最终测试默认冻结经验和效用，不把测试答案写回。若专门研究在线学习，则另设逐任务协议，只使用此前允许获得的反馈，不能看到未来答案；两种结果分开报告。

## 6 与主线的关系及交付

主线研究如何修改和选择策略，记忆副线研究运行时使用哪些经验。先固定一方研究另一方，最后比较“都不用、只用 Skill、只用记忆、两者都用”，才能解释各自贡献。

建议交付经验条目规范、提炼与检索接口、效用更新方法和同预算对照报告。业务角色复核经验适用边界，算法角色负责选择方法，评测角色维护独立测试；具体人员尚待团队决定。

如果少量经验没有稳定收益，或效果与简单少样例提示相当但成本更高，就暂停复杂记忆系统建设。当前尚未实现或验证上述方案。
