# RRSI 的来源与用途

**RRSI 研究怎样约束系统自我改进过程，减少针对训练题的过拟合、无效改动和不值得的成本增加。** 它适合用作候选接受与拒绝机制的研究对照。

## 原始来源

- 论文：[RRSI: Regularized Recursive Self-Improvement of Agent Harnesses，v3](https://arxiv.org/abs/2609.24972v3)；本目录附有 [PDF 原文](../论文/RRSI_2609.24972v3.pdf)。
- 作者公开代码：[google-research/rrsi](https://github.com/google-research/rrsi)。
- 本次适配分析参考的代码版本：[be50316e1db0](https://github.com/google-research/rrsi/commit/be50316e1db05914068a973f322770ef08ed7ba1)。
- 下载方式：进入代码网页选择 `Code → Download ZIP`，或取得上述固定提交。安装、依赖与许可证以仓库原文为准。

## 在我们项目中做什么

智语外呼可能出现“开发分数提高，但错误回写或模型调用成本也增加”的候选。RRSI 已有评测泄漏筛查、噪声容忍、成本规则、编辑历史和无效组件剪枝，可作为判断新策略是否值得保留的基线。

建议先让本项目执行器返回每个任务的业务得分、严重错误和运行成本，再比较 RRSI 式选择与普通固定评分。单纯增加阈值或成本惩罚不能当作我们的创新；潜在研究增量在于如何选择有诊断价值的案例并分配验证预算。

## 需要适配什么

原仓库通过领域适配器接任务环境，并在独立工作树中生成和评估候选代码。本项目初期只开放分类提示词，修改空间更窄；领域、奖励、成本及不可补偿的业务门禁都需要重新定义。

如果只移植选择器，应标为 RRSI 机制对照，不能称为完整论文复现。论文版本和源码提交分别固定，实验设置仍需逐项核对。当前未执行自动改写或候选搜索。
