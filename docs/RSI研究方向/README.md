# 智语外呼 RSI 研究方向与推进建议

**建议把“可靠验证驱动的 Skill 自优化”作为主线，把“经验记忆的有效利用”作为支持副线，先补齐两者共用的评测能力。蒸馏留到有效策略形成之后。** 这是供团队评审的候选方案，尚未确定具体负责人，也没有取得本项目上的算法提升结果。

## 1 我们要解决什么问题

智语外呼项目要让 AI 在语音通话中解释商家资质材料的问题，确认对方的实际意愿，并把沟通结果正确写回系统。基础系统能运行后，还需要回答：它能否从失败中改进，以及我们怎样证明这种改进真的有用。

这里的 RSI 指系统反复执行“运行任务 → 分析问题 → 提出修改 → 验证效果 → 保留或拒绝修改”的过程，不要求先训练一个新的基础模型。Skill 指可复用的任务处理说明或策略，例如遇到含糊回应时如何澄清；它必须被程序实际加载并用于决策，单独写成文件并不会自动生效。

一个典型问题是：商家说“知道了”，系统就把它当作“愿意补齐材料”。这种处理可能让通话更短、模拟用户更容易配合，却记录了错误意愿。研究应减少这类业务错误，而不只是让模型裁判给更高分。

## 2 为什么优先选这些方向

| 定位 | 方向与核心问题 | 已有工作提供了什么 | 本项目建议 |
| --- | --- | --- | --- |
| **MAIN 主线** | 可靠验证驱动的 Skill 自优化：怎样选出真正有效的改动？ | [GEPA](https://arxiv.org/abs/2507.19457)根据执行轨迹反思并优化提示词；[RRSI v3](https://arxiv.org/abs/2609.24972v3)处理过拟合、噪声和成本；[EvoSkill v2](https://arxiv.org/abs/2610.25931v2)研究有状态的技能演化与不同更新方式 | 用现成方法建立对照，再研究“测试哪些案例，才足以判断改动有效” |
| **SECONDARY 支持副线** | 经验记忆效用：哪条经验真正帮助了新任务？ | [ReasoningBank](https://arxiv.org/abs/2509.25140)从成功和失败中提炼经验；[MemRL](https://arxiv.org/abs/2601.03192v2)根据反馈更新经验效用 | 研究经验的适用条件、额外收益和失效时机 |
| **共用前置工作** | 业务结果评测：怎样避免“看起来成功”？ | [τ²-bench](https://arxiv.org/abs/2506.07982)提供用户、Agent、环境与评价的组织方式；[τ-Voice](https://arxiv.org/abs/2603.13686v1)扩展到语音交互 | 结合本项目规则，校验最终业务状态、确认过程与语音表现 |
| **BACKLOG 后续候选** | 蒸馏：怎样把已验证行为交给成本更低的学生模型？ | [GKD](https://arxiv.org/abs/2306.13649v3)研究在学生生成的序列上利用教师反馈 | 等教师策略确实更好、在线成本或时延构成问题后再启动 |

**现成框架的使用不等于方法创新。** 加记忆库、让模型复盘、设评分阈值或划分测试集，都不能单独作为新的研究贡献。潜在增量需要与已有方法在相同条件下比较，再用拆除某个机制的对照实验解释收益来自哪里。

## 3 与当前 ADHD 基线是什么关系

当前基线已经有会话管理、业务状态机、Mock 回写、知识检索和语音链路。Qwen3-8B 主要负责把商家发言归为十类意图；回复和业务动作由状态机及已审核知识决定。因此，现有工程可以继续使用，但外部 RSI 框架需要适配。

- **最小接入点是意图分类提示词。** 将候选提示词实际传入模型，比较原始分类、程序守卫后的结果和最终业务状态。
- **完整沟通 Skill 需要策略接口。** 如果希望系统学习怎样解释或追问，就要允许它提出这些动作，并由程序验证动作是否适用；只优化分类提示词不能完成这一步。
- **经验记忆需要新的使用通道。** 当前检索的是业务知识，尚无跨任务经验库及效用更新。可以先把少量经验用于意图分类，再逐步扩展到沟通策略。

现有 8 条文本开发评测使用规则模拟器，不调用 Qwen，所以不能衡量新旧模型提示词的差异。12 条真实意图样例也已用于开发，且输出经过程序守卫，不能作为独立测试成绩。后续需要补真正运行候选方案的评测入口和未参与调参的测试案例。

上述基线事实来自 ADHD《基线自测报告》（2026-11-08）及代码核查。报告记录的设备为共享 A800 80GB，B0 基线版本尚未完成冻结验收；人声、声学时延、独立业务复核和比赛网络/接口仍有待办。代码定位可选查阅：[模型分类入口](https://github.com/Phosper/ADHD/blob/41afa0c67904de9ef07a5d1445dbcfb86e1e7565/services/api/model_client.py)、[文本开发评测](https://github.com/Phosper/ADHD/blob/41afa0c67904de9ef07a5d1445dbcfb86e1e7565/evals/run_text.py)、[基线自测报告](https://github.com/Phosper/ADHD/blob/41afa0c67904de9ef07a5d1445dbcfb86e1e7565/docs/基线自测报告.md)。

## 4 建议怎样推进

| 顺序 | 做什么 | 这一阶段应该得到什么 |
| --- | --- | --- |
| 先完成共同基础 | 完成基线待验收事项；确认业务答案，准备独立测试与候选执行接口 | 能区分模型错误、业务错误和执行问题，且新旧方案可公平比较 |
| 首先验证主线 | 从分类提示词开始比较原始版本、人工修订与 GEPA | 证明候选真正影响模型，并判断是否有可重复的收益 |
| 再研究方法增量 | 比较固定测试、随机追加测试和根据改动选择诊断案例的方法 | 判断相同预算下是否更少接受无效改动，最终版本是否更好 |
| 有独立人手再扩展副线 | 固定主线版本，验证经验检索与效用选择 | 证明记忆带来的额外收益，而不是重复计算主线收益 |

优先级不代表三个方向同时全面开工。评测是共同基础，主线优先，记忆按资源安排；完整 Skill 接口涉及业务、后端和评测模块，应先共同审阅。按现有任务看板，完成 B0 冻结后再进入 RSI 实施。

## 5 蒸馏简要说明

蒸馏是让较小模型学习较强教师的有效行为。当前直接训练主要对应“更小的意图分类器”，还不是完整外呼策略；应先与简单分类方法比较。若后续教师策略在独立测试中明显更好，但运行成本或时延过高，再考虑教师输出监督训练与 LoRA/QLoRA。完整 GKD 概率蒸馏还需要教师概率和独立训练环境，现有分类接口不能直接满足。参考：[GKD 原论文](https://arxiv.org/abs/2306.13649v3)、[QLoRA 原论文](https://arxiv.org/abs/2305.14314)、[TRL GKD 官方文档](https://huggingface.co/docs/trl/gkd_trainer)。
